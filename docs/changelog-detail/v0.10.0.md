## v0.10.0 (2026-10-27)

Since v0.9.1: forge writes are governed. A `forge-write-consent` hook stops an agent posting a comment or filing a ticket the user did not ask for, with a per-session ticket budget (default 3) so needed tickets still get filed while a runaway session stops at the cap, and a `scan-forge-writes` hook plus forge-lib's own scan check every issue, comment and release text for leaks before it is sent. A checked-out branch can no longer redirect the forge token through `.forge.conf`. Review findings are triaged by severity and by whether they relate to the change, and a fix's own review files only Critical or High, which stops review chains. New: the `usage-report` skill, `FORGE_BODY_FILTER`, `close-shipped.sh` so a release closes what it shipped, `review-mechanics.sh` for `/phase review`, and five new forge-adapt drift reports. Last in: closing-sessions' `memory.py` reaches a Claude Code auto-memory store (#569, #570, #571), and two existing contracts are now written down (#567, #568).

### Security

- forge-host: `FORGE_BODY_FILTER` hardening from review round 1 of #541 (forge-lib 61 to 62, forge-host 55 to 56, forge-kit-devops 0.26.3 to 0.26.4; 5 rows, 6 mutants). A path containing `=` is refused with 111: `env` read it as an assignment, ran no filter and printed the whole environment, which was then sent as the body with rc 0. The default-branch pin now runs before the filter in the caller's shell, so the token variable `.forge.conf` names through `FORGE_TOKEN_ENV` is stripped from the filter too (it was loaded only inside `$(forge_repo)`), and a branch that changes or deletes that key is refused with 2 before the filter starts. The timeout is now `timeout -k 5 10`, so a filter that ignores TERM is killed instead of hanging the call.
- leak-guard: a checked-out branch can no longer weaken the forge-write scan. In both layers (the `scan-forge-writes` hook with its shell gate, and forge-lib's own scan) the sentinel counts when the working copy OR the default branch's tree lists it, and the allowlist is the default branch's `.leak-guard-allow` blob only, so a branch can neither delete a committed sentinel nor add allow entries for itself. The remote and ref follow the pin's rule; no remote at all keeps the working copy silently, and a remote without a readable default ref uses no allowlist with one note. `FORGE_LEAK_SCAN` is library-only, and the hook no longer passes an inherited `ALLOW_FILE` to a scanner (#558). forge-lib 59 to 60, scan-forge-writes 3 to 4, forge-host 53 to 54, leak-guard 35 to 36, forge-adapt 94 to 95, forge-kit-devops 0.26.1 to 0.26.2, forge-kit-security 0.18.3 to 0.18.4, forge-kit-adapt 0.12.30 to 0.12.31.

Behaviour unchanged. forge-kit-security 0.18.7 to 0.18.8.

### Added

- **A `usage-report` skill prints where Claude Code usage went over the last N days, read from the transcripts the CLI already writes** (new skill `usage-report-version` 3 with `scripts/usage-report.py`, `forge-kit-devops` 0.25.0 to 0.26.2; #566; `scripts/test-usage-report.sh`, 12 mutants killed). The dashboards say what it cost; this says why, and on every machine measured the answer was context re-sent, not output. It prints context per turn split into uncached, cache-write and cache-read tokens with the output apart, by project, by model with main and subagent rows separate, by session with its growth from the first main turn to the last, and by UTC day, as tables or one `--json` object; nothing on stdout and exit 2 when the root is missing or no turn falls in the window. The window is applied to a turn after its last line is chosen, so a response whose lines straddle midnight is in one day's report and never in two (review round 1).
