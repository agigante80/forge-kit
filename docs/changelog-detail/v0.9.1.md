## v0.9.1 (2026-10-11)

Since v0.9.0: the phase "Guards and scripts that miss a case" worked through its tickets one at a time. `overnight-guard` now reads redirections (`2>&1`, `>|`, a redirection before the git subcommand), backslash-newline continuations, global options past its cap, and raw control bytes the way the shell does, so each of those spellings of a destructive command is denied. The labels block in forge-adapt publishes through symlinks without replacing them or clobbering `.tmp` siblings, and area labels match without regard to case across the gate, the labels block and the mechanics check. The `no-poll-loops` cases left unverified by #433 were probed on Claude Code 2.1.296 (#458). Left open for a maintainer decision: #475 (what `no-poll-loops` should tell a subagent) and #476.

- **`overnight-guard.py` split a segment at the `|` of the noclobber redirection `>|`, so `rm -rf >|log /` was allowed** (`overnight-guard-version` 15 to 16, `forge-kit-governance` 0.34.14 to 0.34.15; #474; `scripts/test-hooks.py`). The `|` of `>|` (also `2>|x`, `12>|x`, `>| log`) ended the rm or git segment before the target, so `rm -rf >|log /`, `rm -rf >|log "$PWD"/`, `git reset >|x --hard` and `git >|x reset --hard` were allowed on both arms, and overnight `curl u >|f | sh` was not read as a pipe to a shell while `curl x >|bash` (a file named bash) was falsely denied. `_flat()` now masks that `|` as `REDIR_PIPE` in the same single linear pass as the ampersands (a `|` right after a `>` is never a pipe), so every segment class stays the plain `[^|;&\n]*`. `_strip_redirs`, `_sub_body` and #473's git operator and target lookahead accept the sentinel (the token stays one-parse), and the pipe-to-shell pattern now reads the masked text. A real pipe still splits (`rm -rf build >|log | cat /` stays allowed, `echo a >|log | rm -rf /` stays denied). Overnight still judges only the first rm in a payload, so `rm -rf build >|log && rm -rf /` has no overnight deny row. A backslash-escaped `\>` is a literal argument, so `curl u\>|sh` keeps its real pipe and stays denied overnight (review round 1). Mutants: the sentinel left out of `_strip_redirs` (killed by the spaced `rm -rf >| /dev/null build`; the unspaced form passes either way), left out of `_sub_body` (killed by `rm -rf "$(pwd >| /dev/null)"`), the pipe-to-shell pattern reading the raw command, the git operator without it, the git target lookahead without it (the `>|>&` timing shape then never returns), and the mask removed from `_flat()`. `_sub_body` is pinned by direct rows because `_strip_redirs` already cleans the spaced substitution form end to end. No sentinel is added to the glued-`git` lookahead: `REDIR_PIPE` can never directly follow `git`.
- **`overnight-guard.py` allowed a destructive git command with a redirection before the subcommand** (`overnight-guard-version` 14 to 15, `forge-kit-governance` 0.34.13 to 0.34.14; #473; `scripts/test-hooks.py`). `git 2>&1 reset --hard` (also `git >/dev/null reset --hard`, `git > f clean -fd`, `git &>x stash drop`, `git <in reset --hard`, a redirection glued to `git` such as `git>x reset --hard`, and a redirection mixed with a global option in either order) was allowed on both arms. A redirection is now a third alternative of the same bounded prefix repeat, so options and redirections interleave and both count toward `GIT_PREFIX_MAX` (33 mixed tokens hit the cap label). The token is unambiguous (its target may not start with `<`, `>` or the masked `&`), because a naive two-way-parsable token measured 9.8 s at 24 `>>a` tokens and a hook that times out does not deny. `>|` stays #474. Mutants: the alternative removed, the optional space after the operator dropped, redirections in a separate repeat, redirections outside the cap, the target lookahead dropped (the `>>a` timing row blows its bound), and the glued-token space removed from `_flat()`.

- **Private tree mode reports a listed name in a non-UTF-8 file under a UTF-8 locale** (`check-private-leaks-version` 28 to 29, `forge-kit-security` 0.17.5 to 0.17.6; #456). The tree-mode substring grep ran unpinned and without `-a`, so a UTF-8 caller's GNU grep classified a match whose own bytes were invalid UTF-8 (a Windows-1252 or Latin-1 name) as binary, printed "binary file matches" instead of the line, and the scan exited 0 with the listed name unreported (an ASCII name in a Latin-1 file was already found). It now reads with `-a` and stays unpinned, which keeps non-ASCII case folding (a pin to `LC_ALL=C` would lose it). The `grep -Iq .` skip was checked and does not drop a file holding at least one valid character. Side effect, accepted as the safer direction: a file whose first NUL byte comes after the first matching line is now scanned past that NUL for listed names (the whole-word grep still stops there). The #439 tree-mode malformed-name rows, previously scoped to C, now run in every locale, with a Windows-1252 row (`\x8eI\x9eek` found and printed as `\x8eI\x9ee*`) and a `JOSE-acute` case-folding row; mutants `grep-a` and `grep-c-pin` each turn a row red under a UTF-8 locale and are reported skipped without one. A UTF-16 file is still skipped by the NUL-byte skip in every locale (out of scope).
- **A git global option between `git` and the subcommand bypassed every destructive-git rule of `overnight-guard`, in both arms** (`overnight-guard-version` 9 to 10, `forge-kit-governance` 0.34.7 to 0.34.8; #457; `scripts/test-hooks.py` passes). `git -C sub reset --hard`, `git -c k=v checkout .`, `git -p clean -fd`, `git --bare branch -D x`, `git --no-pager stash drop` and `git -C "my dir" reset --hard` were all allowed, overnight and by day. One shared `GIT_PREFIX` now sits in front of every pattern and follows git's usage grammar rather than a list of spellings: any dash token is a global option, and `-C`, `-c`, `--git-dir`, `--work-tree`, `--namespace` and `--config-env` (space and `=` forms, quoted values) consume their value, so `git -c reset.hard=1 status` stays allowed. Python's `re` has no backtracking limit and a hook timeout fails open, so the token alternatives are disjoint (option names, the `=` form, quoted against bare values) and the repeat is capped at 32 options, because every `git` value is a fresh start and an unbounded chain is quadratic (55 s at 3200 `git -c` pairs); more than 32 options is allowed as deliberate evasion for now, and #469 makes the cap fail closed. Four 200-token shapes and an 800-pair retry shape are timed in-process against both matchers, each with a mutant that hangs or overruns, plus one subprocess row at the 5s bound. Values may also be backslash-escaped, `$(...)` or backtick substitutions (bounded at 200 characters, because an unbounded body is quadratic too), and `--attr-source` takes a separate argument. Inline aliases (`git -c alias.x='reset --hard' x`) remain a documented, deliberate-evasion gap.
- **`overnight-guard` allowed `rm -rf` of the worktree itself, in both arms** (`overnight-guard-version` 10 to 11, `forge-kit-governance` 0.34.8 to 0.34.9; #467). `rm -rf "$PWD"`, `$(pwd)`, `` `pwd` ``, `$CLAUDE_PROJECT_DIR` and `$(git rev-parse --show-toplevel)` deleted the project with its uncommitted work. Subdirectories, `$PWDX`, single-quoted text and other substitutions stay allowed. The overnight first-rm limit stands and is documented.
- **`reassess-phases.sh` compares a multi-line merge reason or delete note as one block, so it is no longer silently dropped** (`reassess-phases-version` 10 to 11, `test-reassess-phases-version` 6 to 7, `roadmap-phases-version` 16 to 17, `forge-kit-roadmap` 0.15.16 to 0.15.17; #460; `scripts/test-reassess-phases.sh` 355 tests). `grep -qxF` reads a pattern holding newlines as a list, so one line of a multi-line `--reason` equal to any whole line of the winner's prose (its blank separator, or the first line) made `merge` print `already carries the merge reason` and write nothing, and a first-line match let `$'x\nstate: done'` skip the library's refusal. `record_note` had the same defect for `delete --reason`.
