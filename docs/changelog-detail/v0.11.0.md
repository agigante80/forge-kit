## v0.11.0 (2026-11-13)

Since v0.10.0: agents no longer post comments for decisions, gate reviews or release notes; those go in the ticket body, under one canonical rule. The public documentation was rebuilt (#572) and the repository gained its MIT licence, a security policy and a contributing guide. CI runs on ubuntu 26.04 again.

### The comment rule: decisions go in the ticket body

- **One canonical comment rule** (#585; `comment-rule` v2 in `scripts/rules.tsv`, `doc-rules-version` 25 to 26, `forge-write-consent-version` 9 to 10, `decision-brief-version` 7 to 8, `ticket-gate-version` 93 to 94, `forge-kit-governance` 0.40.5 to 0.40.6, `forge-kit-adapt` 0.13.15 to 0.13.16; `scripts/test-check-rules.sh`, `scripts/test-hooks.py`). A comment is posted only when the user asks, to explain something to another person, or on a ticket that is not ours; decisions, corrections, retractions and closing notes are body edits (the `Released in <tag>` note moved to the body in #583). The rule lives once, in `docs/guides/ticket-standards.md` ("Comments on tickets"); `forge-write-consent`, the hooks README and `decision-brief` carry its id instead of their old wording, which `retired-rules.tsv` retires as v1. The hook still denies every ungranted comment; #586 removed its exemptions.

- **The ticket gate posts no comment: its review is a body region** (#581; `ticket-gate-version` 89 to 92, `ticket-gate-reference-version` 16 to 17, `gate-ticket-version` 10 to 11, `gate-env-version` 3 to 6, `count-gate-rounds-version` 3 to 6, `gate-status-version` 13 to 14, `forge-kit-governance` 0.39.0 to 0.40.1; `scripts/test-count-gate-rounds.sh`, `test-gate-status.sh` and `test-gate-env.sh`). The maintainer ruled a third time that the gate writes zero comments. The full review is the new `gate-review` region (heading `Gate review (round N)`), replaced each round with the previous one in the forge's edit history; the synthesis void note rides at its top, the clarification questions and the prompt-mode remediation guide are body regions too, and a body that would pass about 60,000 characters gets a shortened review, never a comment. `count-gate-rounds.sh` takes the round from the highest round heading in the gate regions or the count of legacy `Ticket Readiness Review` comments, whichever is higher, and warns on stderr in the one case it cannot see (the author deleted the regions on a ticket with no legacy comments); `--memory` reads the body's `gate-required-changes` checklist first. The stamp drops `Full review: <url>` (fingerprint and `fp11` unchanged, so no ticket changes state), and `forge_gate_comment` is removed from `gate-env.sh`. `forge-write-consent` still names it in its docstring and self-test (tracked in #586). Round 1 review fixes: Step 0c records the round before it clears the regions and writes a `Gate review (round P)` heading with the void note at once (so a stop after 0c keeps both the count and the note); one `gate_write_review` helper in `gate-env.sh` does every review write and measures the CURRENT body for the size cut; `count-gate-rounds.sh` is fence-aware, portable (no GNU `\|`), and `--memory` refuses an older legacy comment when the body is on a newer round. `ticket-gate` shrinks 7 words in all (baseline 5632 to 5624). Round 2: Step 1.5 appends the clarification to the review 0c-v wrote (a 0c plus 1.5 run no longer resets the count), `gate-review` joins the reset-warning trace, and `gate_write_review` adds no Cut line when nothing was cut. Live runs (#582 to #586, zero comments posted): 0c-v's void note on a first run carries a `Gate review (round 0)` heading, so the reset warning no longer fires on every first gate of a hand-filed ticket (`count-gate-rounds-version` 7, `ticket-gate-version` 93, `forge-kit-governance` 0.40.3), and the Step 2.9 context example drops the marker lines `forge_body_region_set` refuses (baseline 5624 to 5620).

- **`/phase review` rewrites a ticket's body without posting the old one as a comment** (#582; `roadmap-phases-version` 20 to 21, `phase-version` 17 to 18, `review-mechanics-version` 1 to 2, `forge-kit-roadmap` 0.15.22 to 0.15.23; `scripts/test-review-mechanics.sh`). The suite gains a static check that both prose files carry no retired phrase and no `` `preserved` `` row token (the bare word is allowed), and two mutants.

(already closed)`; report mode is unchanged and never reads the region. - **`/ci-health` writes its investigate-only notes in the ticket body, never a comment** (#584; `ci-health-version` 14 to 15, `forge-kit-devops` 0.26.9 to 0.26.10; `scripts/test-ci-health-host.sh` 62 to 68 tests). Phase 4's DO NOT AUTO-IMPLEMENT list still said "comment" for E2E failures, security scan findings and Release / version-gate failures, so a finding sat where the next agent does not read. The three cases now call `forge_body_region_set "<N>" ci-health ci-health-notes`, a region of its own (`ci-health-status` stays the Forgejo status region), and a second note on the same ticket replaces the region. The suite fails when any posting command appears in the file, when a case lacks the region write, or when a bullet says comment again, each with a mutant.

- **`forge-write-consent` exempts no comment** (#586; `forge-write-consent-version` 8 to 9, `forge-kit-governance` 0.40.4 to 0.40.5; `scripts/test-hooks.py`). The hook allowed three comments without `allow-comment`: a `Released in <version>` note, `forge_gate_comment`, and any `gh issue close --comment`, which could park a whole decision where body readers never look. With #581 and #583 merged nothing in the kit needs them. `RELEASE_NOTE` is gone, `gh issue|pr close|reopen` with `--comment`, `--comment=` or `-c` (flags in any order) is a comment write, and `forge_gate_comment` (still defined by an older installed gate-env.sh) is judged like `forge_issue_comment`. The suite moves the release and gate cases to the deny list, adds the close and reopen forms and granted-flow rows, drops the two mutant rows whose anchors were the removed code, and adds four mutants: each exemption put back, and the close and reopen rules dropped.

- **forge-write-consent can turn the ticket rule off** (`forge-write-consent-version` 7 to 8, `forge-kit-governance` 0.38.1 to 0.38.2; `scripts/test-hooks.py`). A `ticket-budget: unlimited` line in `.claude/forge-write-consent` means no ticket write is judged, counted or denied, loops included, so a maintainer who wants tickets filed freely no longer writes `allow-ticket` each time. Comments still need `allow-comment`. Any other non-numeric value still fails closed to 0, `Unlimited` included.
